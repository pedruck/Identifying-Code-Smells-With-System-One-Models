# Identifying code smells with System One models

Can the contrastive verifier **CLM-v0.1-8B** (frozen Qwen3-8B encoder plus trainable projection heads) be
fine-tuned to detect code smells across programming languages, and does that transfer to unseen languages?

This repository implements the approved experimental plan (PED-2, revision 4): a staged, resumable Colab
pipeline built on the **unmodified official CLM release** (`Contrastive-LM/CLM` @ `bb42c6c`). It does not use
generative SFT, LoRA or QLoRA.

## Running

Colab: open `notebooks/clm_code_smell_pilot.ipynb` on a GPU runtime with at least 22 GB VRAM and run top to bottom.

Headless:

```bash
tools/setup_clm.sh --install && pip install -e ".[gpu,dev]"
python -m smellclm.pipeline --config configs/stage1.json --root runs
# CPU-only check of stages 1-3 (smoke mode):
python -m smellclm.pipeline --config configs/stage1.json --root runs --until 03_split --allow-cpu-only
pytest
```

## Design choices worth knowing

- **Binary questions** use the official `noul` type: one question per (sample, smell), candidates `false`/`true`
  with symmetric definitions. The margin `logit_true - logit_false` is the score.
- **Official trainer, unmodified.** Row `id` is the split group, so the trainer's own early-stopping carve-out is
  repository-family-disjoint. Its `test` file receives our validation split. The locked test split never reaches it.
  Checkpoint selection is therefore by the trainer's validation accuracy, not macro-F1. This is a documented
  deviation that keeps the official code untouched. Thresholds are then chosen on our validation split.
- **Truncation is never silent.** The official recipe keeps the last `max_len - 1` tokens. Stage 4 counts tokens
  and excludes truncated decisions, reporting them per split.
- **Exact duplicates** are collapsed before splitting; clusters with conflicting labels are dropped. Near and
  renamed clones of non-trivial snippets (≥ 40 tokens) merge split groups.
